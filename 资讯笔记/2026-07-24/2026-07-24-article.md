# 从"能看不能动"到"直接改价格"：AI Agent 这次拿到了销售流程的写权限

一份报价单从销售提出折扣、到财务审批、再到最终开票回款，中间往往要跨好几个系统、经过好几个人手动确认——AI Agent 这两年虽然已经能帮销售起草报价、回答客户问题，但走到"改价格""发合同""催回款"这类真正牵动钱的环节，大多数企业还是不敢把权限交出去，AI 最多只能"看"，不能"动"。

B2B SaaS 报价到回款（Quote-to-Cash，QTC）平台 Turnstile 为"人类 + Agent"混合团队推出读写（read-and-write）双向 Model Context Protocol——这意味着 AI Agent 不再只是读取定价、合同、账单这些数据，而是能直接控制整个 QTC 流程，自动完成审批、催收等原本需要人工操作的环节。

## 从"看着办"到"直接办"

过去企业给 AI Agent 接入业务系统，大多止步于"只读"权限——Agent 可以查订单、看合同、拉数据做分析，但凡涉及修改状态、触发流程的操作，还是得交还给人工去点按钮。这种设计的逻辑很好理解：企业不放心把"能改钱"的权限交给一个不能完全预判行为的 AI。Turnstile 这次的读写 MCP，把权限边界往前推了一步——Agent 可以直接读取企业的定价、合同、账单和客户上下文，并基于这些"可信基础"去执行审批、催收这类实际操作，而不只是给人类提建议。简单来说，以前 AI 是"看着办"，现在 AI 是"直接办"。

Turnstile 官方给这套系统的定位是"目前业内少数支持 Agent 对 QTC 全流程做控制，而非仅提供数据访问的 MCP"——换句话说，大部分同类产品目前还停留在"给 Agent 开一个只读接口"的阶段，Turnstile 这次是把写权限也放开了。这个转变背后想解决的问题也很具体：让人类和 Agent 团队基于同一套可信的业务上下文协同工作，做的是"AI 驱动的收入运营"，而不是简单的、预先写死规则的确定性工作流。

## 从融资故事到一个能用的功能

Turnstile 今年 2 月刚完成 2900 万美元 A 轮融资，还是一家规模不大的早期创业公司，这次读写 MCP 的推出，某种意义上是把融资故事里"AI 原生 QTC"这个概念，兑现成了一个具体可用的产品能力。对企业销售团队来说，这意味着"AI 辅助人类操作"正在往"AI 直接执行交易闭环"的方向走——一份报价从提出到最终收到回款，理论上可以由 Agent 和人类共用同一套系统、同一套上下文，协同推进，而不是靠 Agent 写完建议再交给人复制粘贴到另一个系统里执行。简单来说，以前 Agent 和人类是两套系统里各干各的，现在是同一套系统里分工干活。这条路能走多远，还得看它自己的客户规模能不能跟上。

从"AI 只能看不能动"，到"AI 能直接改价格、能推进回款"，销售流程自动化正在把决策权一点点交出去。这一步能不能走稳，取决于企业敢不敢真的把"能改钱"的权限给到 Agent——但至少现在，技术上已经不再是障碍。

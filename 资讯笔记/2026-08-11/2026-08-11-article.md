# 一个模型，95%的概率能帮你挖到能利用的漏洞

一名安全研究员想在 Chrome 的 V8 引擎里找一个能被利用的漏洞，这活儿以前基本靠"啃"——读源码、猜内存布局、手动构造 PoC，一个能真正串成攻击链的漏洞，可能要磨上几周甚至几个月。现在这件事的耗时和成功率，正在被一个专门训练出来的模型改写。

OpenAI 宣布扩容其网络安全计划 Daybreak，拆分成 Daybreak Blue 和 Daybreak Red 两档，并发布了一款专供授权安全研究者使用的定制模型 GPT-5.6-Cyber，专注漏洞挖掘、渗透测试与补丁验证。

## 不是"更强的通用模型"，是"专门为攻防训练"的模型

Daybreak Blue 和 Daybreak Red 的区别，本质是"松绑程度"的区别。Blue 面向的是日常安全工作，把通用旗舰模型 GPT-5.6 Sol 的安全防护适度放宽，方便做常规的合规防御工作；Red 则是更高门槛的申请制通道，只有通过审核的安全研究者才能拿到 GPT-5.6-Cyber——这款基于 GPT-5.6 Sol 训练、专门用于漏洞挖掘和攻击链构造的模型。简单来说，以前"能不能帮你干这活"取决于你问得够不够巧妙地绕过模型的安全限制，现在 OpenAI 干脆把"能干这活"的能力单独训练出来一个模型，再用申请审核去控制谁能用。

这个"专门训练"带来的差距是量化过的：按 OpenAI 内部的 Advanced Cybersecurity Completion Rate 评测，在涉及攻击链构造、身份验证绕过、权限提升这类任务上，GPT-5.6-Cyber 的任务完成率是 95%，而标准版 GPT-5.6 Sol 只有 1.5%。这不是同一个模型放宽限制后的差异，而是两种训练目标带出来的能力鸿沟——通用模型天然会在这类任务上"退缩"，专用模型则被直接训练成"往前冲"。

GPT-5.6-Cyber 已经拿到过真实战绩：OpenAI 用它排查 Chrome 的 JavaScript 引擎 V8，找到了两个此前未知的漏洞，能被串联起来破坏内存并逃出 V8 的堆沙箱，其中一个已经拿到编号 CVE-2026-15903。对安全研究圈子来说，"发现漏洞"和"发现一个能被 CVE 收录、经得起同行核验的漏洞"完全是两回事——后者意味着这个漏洞真的被验证、真的可以被复现，而不是模型自己觉得"这里可能有问题"。这是能拿去核实、能对上公开漏洞库编号的实打实结果，不是营销话术里的"通过内部测试"。

## 攻防两用能力，第一次被系统性分级管控

把一个"既能挖洞也能被拿去攻击"的能力做成产品，最大的争议点从来不是能力强不强，而是怎么管住它不被滥用。这次 Daybreak 的两档设计，其实是大模型厂商第一次把"攻防两用"能力做成了一套分级管控体系——通用能力开放给更大范围的防御者，最锋利的那部分能力，用申请制拴在一小群经过审核的安全研究者手里。简单来说，以前是"一个模型，靠你怎么问来决定它帮谁"，现在是"两个版本，靠你是谁来决定你能拿到哪个"。目前公开信息里还没有披露 Daybreak Red 的具体审核标准和通过率，这类细节通常要等项目运行一段时间、出现争议或案例后才会被披露。

从行业背景看，这也是 AI 安全军备竞赛进入新阶段的一个信号：当模型挖漏洞的效率已经能把"几周"压缩到可量化的"95%完成率"，攻击方拿到同等能力只是时间问题，防御方能不能同步拿到并用好这类工具，直接决定了这场竞赛谁先掉队。GPT-5.6-Cyber 能不能持续产出像 CVE-2026-15903 这样能被验证的成果，会是判断这套分级管控体系是否真的管用的关键指标。
